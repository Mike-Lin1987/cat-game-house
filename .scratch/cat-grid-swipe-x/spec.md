Status: ready-for-agent

## 問題陳述

手機玩家目前只能逐格點按來加入 X 筆記。棋盤較大時，連續標記多個排除格需要大量重複點按，操作速度慢，也容易在快速點按時誤觸既有的放貓循環。

## 解決方案

在貓咪方格的棋盤提供滑動標記：玩家從空格按住並滑過多格時，沿途每個空格都加入 X 筆記。滑動不改寫既有 X 筆記或貓咪格，放開手指後結束本次手勢。既有點按與鍵盤操作維持不變。

## 使用者故事

1. 身為手機玩家，我希望按住空格並滑過多格來連續加入 X 筆記，以便快速標記排除格。
2. 身為手機玩家，我希望每個格子在同一次滑動中最多處理一次，以免手指輕微來回時反覆切換標記。
3. 身為手機玩家，我希望滑過既有 X 筆記時保持原狀，以免意外清除先前的推理。
4. 身為手機玩家，我希望滑過貓咪格時保持原狀，以免意外改寫已放置的貓咪。
5. 身為玩家，我希望單次點按仍遵循原本的格子循環規則，以便繼續使用熟悉的操作。
6. 身為鍵盤玩家，我希望鍵盤操作維持可用，以免新觸控功能影響無障礙與桌面操作。
7. 身為離線玩家，我希望滑動標記不依賴網路或第三方程式，以便在 `file://` 與 PWA 離線模式使用。

## 實作決策

- 滑動標記只在遊戲棋盤啟用，並使用瀏覽器原生 Pointer Events 同時支援手指、觸控筆與滑鼠拖曳。
- 手勢必須從空格開始；開始後，指標進入的每個空格都加入 X 筆記。
- 同一次手勢以已處理格集合去重，避免來回滑動造成重複動作。
- 已有 X 筆記或貓咪的格子不被滑動改寫。
- 真正發生滑動標記後，抑制該手勢產生的後續 click，避免既有點按循環再處理一次。
- 點按、雙次短點放貓、鍵盤、歷史紀錄、步數與完成判定沿用現有行為。
- 不新增 runtime dependency、網路請求或 ESM，保留 `file://` 執行與 PWA 離線相容性。

## 測試決策

- 主要 seam 為真實瀏覽器中的棋盤互動，使用 Pointer Events 模擬按住、移動、放開，觀察可見的 X 筆記。
- 驗證沿途空格加入 X、既有 X 與貓咪不被改寫、同一格不重複處理，以及手勢結束後沒有額外 click 副作用。
- Node UI contract 測試固定公開 Pointer Events、觸控樣式與玩家指引的必要契約，不讀取私有手勢狀態；滑動去重與 click 抑制由真實瀏覽器 QA 驗證。
- 回歸驗證既有點按循環與鍵盤操作，並執行專案完整 Node 測試、離線稽核、build 與瀏覽器 QA。
- 測試只觀察玩家可見行為，不直接測試私有手勢狀態。

## 不在範圍內

- 滑動移除 X 筆記。
- 滑動放置或移除貓咪。
- 調整關卡資料、核心解題規則、進度格式或教學影片。

## 補充說明

- 滑動距離與越格行為由實際命中的棋盤格決定；未經過的格子不自動補線。
- 不建立 ADR，因為這項互動選擇容易調整、符合既有 Pointer Events 慣例，且沒有不可逆的架構取捨。
